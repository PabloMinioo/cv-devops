La API

– visitantes registrados

Una API en Spring Boot y PostgreSQL que guarda los nombres como el que acabás de escribir. Es simple a propósito: sirve para tener tráfico real que monitorear.

  • POST /api/visitors guarda un visitante
  • GET /api/visitors/count cuántos hay

Contenedores

Cómo empaqueto la aplicación y ordeno su ejecución.

  • Dockerfile multi-stage (dependencias, desarrollo, build y producción): imagen final liviana, sin herramientas de compilación y con usuario no root.
  • Docker Compose con dos archivos (aplicación y monitoreo), redes separadas y volúmenes con nombre.
  • Healthchecks y depends_on con service_healthy para que cada servicio arranque cuando sus dependencias están listas.

CI/CD

Cómo se valida, se construye y se publica cada cambio.

  • Pipeline en GitHub Actions: valida los Compose, construye la imagen, la escanea con Trivy y la publica en GitHub Container Registry.
  • El escaneo falla ante vulnerabilidades altas o críticas con parche disponible.
  • Dependabot mantiene al día las imágenes, las actions y las dependencias.

Monitoreo

Qué mido, cómo me entero de los problemas y dónde lo veo.

  • Prometheus recolecta métricas de la API, la base de datos, los contenedores y el servidor.
  • Reglas de alerta sobre síntomas (errores, latencia, recursos) y no solo sobre caídas, gestionadas con Alertmanager.
  • Un único dashboard en Grafana, provisionado desde el repositorio.

Logs

Cómo hago que los logs de todos los servicios se puedan leer en un solo lugar.

  • Alloy recolecta los logs de los contenedores y Loki los almacena.
  • Cada línea recibe un nivel (info, warn, error), los stack traces se unen en un solo evento y se descarta el ruido.
  • Pocas etiquetas de valores fijos, para no inflar el almacenamiento.

Seguridad

Qué decisiones tomé para reducir la superficie de ataque.

  • Contenedores con no-new-privileges y sin capacidades de Linux; se devuelven solo las imprescindibles.
  • Contraseñas generadas en el primer arranque, sin secretos en el repositorio, y puertos publicados solo en localhost.
  • Escaneo de vulnerabilidades con Trivy dentro del pipeline.
